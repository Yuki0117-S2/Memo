▸ 로컬 LLM 지시문 작성법
7원칙
  1. 역할을 한 줄로 못박는다. "너는 MiniMax H3 프롬프트 생성기다." 그 외 잡담·요약·인사는 전부 금지 대상으로 명시한다.
  2. 출력 형식을 강제한다. 아래 필드만 출력. 서두·마크다운·코드펜스·설명 금지. 이 문장이 없으면 열에 아홉은 "물론이죠!"로 시작한다.
  3. 완성 예시를 하나 통째로 붙인다. 규칙 열 줄보다 실제 출력물 1개가 훨씬 강하게 먹는다.
  4. 금지 목록을 따로 판다. 로마자 표기 금지 / <d> 안에는 언어태그와 대사만 / 대사를 soundscape에 넣지 말 것 / 음색은 화자 소개 문구에.
  5. 규칙과 내용을 분리한다. system에는 규칙만, user에는 이번 장면만. 매 요청마다 규칙 전체를 다시 붙이지 않는다.
  6. 샘플러를 조인다. temperature 0.6~0.8, 형식이 깨지면 0.4까지. repeat_penalty 1.05~1.1. 창작 온도가 아니라 서식 온도다.
  7. 분량 상한을 숫자로 박는다. 350~500 words. 안 박으면 끝없이 늘어지고 타임코드가 무너진다.
모델별 차이 · 작성법 자체는 9할이 공통
Qwen 계열
system 롤이 정식으로 분리돼 있어 규칙 유지가 안정적이다. 대신 묘사가 밋밋해지기 쉬우니 "빛·질감·소리 최소 3종 포함" 같은 하한선을 강제한다.
Gemma 계열
채팅 템플릿에 system 롤이 따로 없어 규칙이 첫 user 턴에 합쳐진다. 그래서 프롬프트 맨 끝에 형식 규칙을 한 번 더 반복해야 한다. 상상력이 넘치는 쪽이라 "지정 안 한 요소 추가 금지"로 눌러준다.
체급
영상 프롬프트 조립은 26B 안팎이 실사용 하한선이라는 게 커뮤니티 중론. 8~9B는 필드 누락과 타임코드 붕괴가 잦다.
MoE vs Dense
Dense는 일반 RAM으로 오프로드하면 속도가 급락한다 — VRAM에 전부 올리는 게 원칙. MoE는 비활성 전문가를 RAM에 두고 굴릴 수 있다. mmproj를 같이 물리면 이미지 분석이 되지만 VRAM을 더 먹는다.
시스템 프롬프트 원본 · 그대로 붙여 쓸 것
검증 상태 — 해상도·화소 계산은 산수라 확실하다. 7원칙과 시스템 프롬프트는 모델 무관하게 통하는 일반 원칙이다. 반면 특정 세대 모델의 파라미터·아키텍처 명명(예: Gemma4 26B A4B, Qwen 3.5 27B)은 확인 불가 — 커뮤니티 전언이므로 실측으로 검증할 것. "Qwen이 지시문에 충실하고 Gemma가 상상력이 풍부하다"는 평가도 벤치마크 근거는 불확실함이며, 위에 적은 템플릿 구조 차이는 사실이나 그것이 성능 차이의 전부라는 보장은 없다.
